# Native DLSS 5 Neural Rendering (AMD) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** DLSS 5 NR (mochizuki0323's DLSSNR-AMD network) as a render-resolution pass right before AMD FSR 4.1.2 in `vk_bb_temporal_dlss.cpp`, driven by F1 and `dlss.ini`, with no OptiScaler and no proxy DLL.

**Architecture:** A small add-on DLL of our own, `dlssnr-amd\shadps4_nr.dll`, built with mingw in CI from the pinned mochizuki sources plus one wrapper file, exports a six-function C ABI. shadPS4 loads it only when it and the model exist, creates its device through it (mochizuki's own feature augmentation), hands it the graphics queue with our queue lock, and calls it once a frame on our command buffer, in place on a render-size copy of the upscaler's colour input.

**Tech Stack:** C++20 / vulkan-hpp (shadPS4, MSVC/clang-cl in CI), C++17 mingw-w64 (add-on), GitHub Actions.

**Spec:** `docs/superpowers/specs/2026-11-04-native-nr-design.md`

## Decisions changed from the spec (read at the pinned tag)

The spec left these to "after reading `nr_ngx_core.cpp`". Read; the evidence:

1. **Our own C-ABI wrapper over their model, not their NGX core.** `NVSDK_NGX_VULKAN_Init` in their core declines on Vulkan unless MinHook already watched `vkGetDeviceQueue` (`nr_dlssnr_model.cpp` `vk_init`: "no VkQueue known for this device"). The measured reference setup did not use the core either: the Windows `optiscaler` route installs `dlssnr-amd.asi` (`install.ps1:651`), whose Vulkan path is `note_device` + `vk_init` + `create_vk_asi` + `evaluate_vk_asi` (`nr_asi_main.cpp:5088`, `run_renodx_vk`). The wrapper calls exactly those, so the same code produces the same picture, and no NGX parameter block (MSVC vtable order) crosses the boundary.
2. **Device features: their `nr::pe::vkdevice::create_with_network`**, made for "a vkCreateDevice seen by someone other than the watcher". It adds the network's extensions and features (`vulkanMemoryModel`, FP8 cooperative matrix, `bufferDeviceAddress`), ACO Mode's pipeline binaries, marks the device so the session uses buffer device addresses (`Session::Impl::make_host`), and retries as asked on failure. No hand-written feature list in shadPS4.
3. **Location:** `dlssnr-amd\shadps4_nr.dll`. The wrapper calls `nr::pe::set_module(<exe module>)` first, so their root is the exe folder and the data stays where mochizuki's installer puts it (`dlssnr-amd\dlssnr.bin`, `shaders\`, `aco\`, ..., `dlssnr-amd.ini` and `dlssnr-amd.log` next to `shadPS4.exe`).
4. **Queue lock:** their background builds submit on our graphics queue. Present takes `present_mutex` (Keep rendering while presenting, separate present queue) or `submit_mutex`, then `submit_mutex`; the lock callback takes both with `std::lock(Scheduler::present_mutex, Scheduler::submit_mutex)`. It must be set after `vk_init`, because `Session::set_vulkan_queue` clears it.
5. **NR image:** NR runs in place on our own render-size image (copy of `linear ? linear_color : snapshot`), never on `snapshot` itself, which the HUD delta still reads.

## Global Constraints

- Upstream: `https://gitlab.com/mochizuki0323/DLSSNR-AMD.git`, tag `v0.0.8.2`, commit `c53878b5f0ee1656e740fdbbfd52994d02fe7bd5`. Bumping is a deliberate commit. Their deps come from their own `fetch_deps.sh` at that commit (one source of pins).
- RX 9000 only; NR offered only with `upscaler=amdfsr` (Backend::AmdFsr).
- Files absent (`dlssnr-amd\shadps4_nr.dll` or `dlssnr-amd\dlssnr.bin` missing, or `SHADPS4_NR=0`): no change at all in behaviour, device features, extensions, log or frame time.
- No NVIDIA code or files in this repo or in any artifact. The add-on ships no model.
- The 80 s network build never blocks rendering: frames pass through until ready.
- Any failed load, init or evaluate unloads NR, logs once, leaves upscaling untouched (pattern of commit 5a718613).
- `dlss.ini` keys: `nr` (0/1, default 0), `nr_network` (`auto` | `silver` | `small`, default `auto` = small if `dlssnr-amd\dlssnr-small.bin` exists, else silver), `nr_scale` (0.33..1.00, default 0.67), `nr_intensity` (0..2, default 1.0).
- No local builds (no mingw, no compiler in WSL): every build comes from CI; Robert approves each push. Never launch the game or emulator.
- Commits single-line; no push without explicit per-request approval; no AI attribution in commits or PR text.
- New files: SPDX header `Copyright 2026 Robert Bopko` (his authorship, as `vk_retro_hdr.cpp`); `src/` files `GPL-2.0-or-later`, `dlssnr_addon/` files MIT. clang-format clean (CI `clang-format-23` on the PR range).

```c
#define SHADPS4_NR_ABI_VERSION 1u
typedef struct ShadNrImage { uint64_t image; uint32_t format, width, height, layout, usage; } ShadNrImage;
typedef struct ShadNrFrame {
    ShadNrImage color;   /* read and written in place, VK_IMAGE_LAYOUT_GENERAL, STORAGE usage */
    ShadNrImage depth;   /* SHADER_READ_ONLY_OPTIMAL; image 0 = none */
    ShadNrImage motion;  /* SHADER_READ_ONLY_OPTIMAL; image 0 = none */
    uint32_t width, height;                 /* render size: the colour's working extent */
    uint32_t output_width, output_height;   /* the upscaler's output, for RenoDX's note_pass */
    float mv_scale_x, mv_scale_y;
    uint32_t depth_inverted, reset;
} ShadNrFrame;
typedef struct ShadNrSettings { int32_t network; float scale; float intensity; } ShadNrSettings; /* network: nr::NetworkChoice, 0 CC_SMALL_FP8, 1 CC_SILVER_AARDWOLD */
enum { SHADNR_IDLE = 0, SHADNR_BUILDING = 1, SHADNR_RUNNING = 2, SHADNR_FAILED = 3 };
typedef struct ShadNrStatus { uint32_t state; float network_ms, gpu_ms; uint32_t width, height; char network[32]; char message[224]; } ShadNrStatus;
typedef void (*ShadNrQueueLock)(void* context);

SHADPS4_NR_API uint32_t shadps4_nr_abi_version(void);
SHADPS4_NR_API VkResult shadps4_nr_create_device(PFN_vkCreateDevice create, VkPhysicalDevice physical, const VkDeviceCreateInfo* info, const VkAllocationCallbacks* allocator, VkDevice* out, uint32_t* features_added);
SHADPS4_NR_API int32_t shadps4_nr_init(VkInstance instance, VkPhysicalDevice physical, VkDevice device, uint32_t queue_family, ShadNrQueueLock lock, ShadNrQueueLock unlock, void* context); /* 0 = ready */
SHADPS4_NR_API int32_t shadps4_nr_evaluate(VkCommandBuffer cmd, const ShadNrFrame* frame, const ShadNrSettings* settings); /* 0 = ran or passed through (building), < 0 = failed: unload */
SHADPS4_NR_API void shadps4_nr_status(ShadNrStatus* out);
SHADPS4_NR_API void shadps4_nr_shutdown(void);
```

Plus `static_assert`s on `sizeof(ShadNrImage) == 32`, `sizeof(ShadNrFrame) == 128`, `sizeof(ShadNrSettings) == 12`, `sizeof(ShadNrStatus) == 276` (both compilers see the same header, so a layout drift fails one of the two CI builds).

- [ ] **Step 2: Write `dlssnr_addon/shadps4_nr.cpp`**

One `nr::dlssnr::Feature*` and its size, a mutex, and the last status. Behaviour per export:
- `DllMain` (PROCESS_ATTACH): `nr::pe::set_module(GetModuleHandleW(nullptr))` before anything can log.

A result other than Success, or `session.failed()`, returns -1.
- `shadps4_nr_status`: under `with_vk_session`: state from `building()` / `failed()` / ran, `network_ms()`, `gpu_ms()`, `status()` into `message`, the network codename (`nr::network_codename`) into `network`.
- `shadps4_nr_shutdown`: `release_vk(feature)`, `nr::dlssnr::vk_device_destroyed()` (waits idle, drops the session).

Include the MIT notice of mochizuki's code in the file header comment, ours under MIT.
